## 2. Critical findings

### C-01 — New-user onboarding cannot succeed (plan tier + RLS bootstrap) ✅ (live DB caveat)
- **Files:** `apps/web/src/app/onboarding/page.tsx:15,75,173` · `supabase/schema.sql:15,86-94`
- **Evidence:**
  - Onboarding defaults to and writes `plan_tier: 'professional'`, but the schema CHECK allows only `('starter','pro','business','enterprise')` → every onboarding insert fails the constraint check.
  - Independently, `wf_organizations` and `wf_organization_members` RLS policies are `FOR ALL USING (id IN (SELECT org_id FROM wf_organization_members WHERE user_id = auth.uid()))` with no `WITH CHECK` and no INSERT policy. Postgres applies USING as the INSERT check, and a brand-new user has no membership row → both inserts are denied for the anon browser client.
- **Impact:** signup → `/onboarding` is a dead end (dashboard redirects back while the user has no org). Only the service-role auto-create path in `runner-auth.ts:233-254` can create an org today, and that path conflicts with onboarding's premise (it may silently drop users into an auto-named workspace). Note: `'professional'` appears nowhere else; the other signup path uses `'pro'` (`AuthCard.tsx:21`).
- **Caveat:** verifiable only against the repo SQL. If the live Supabase project has extra out-of-band policies or a different CHECK, part of this is void — **confirm against the deployed schema**.
- **Fix direction:** unify plan tiers to the schema vocabulary; create the first org + owner membership via a server route using the service-role client (or add explicit `WITH CHECK` INSERT policies + a bootstrap RPC).

### C-02 — Duplicate execution race: same-status PATCH bypasses CAS, daemon executes stale candidates ✅
- **Files:** `apps/web/src/app/api/v1/runs/route.ts:268,316-324` · `packages/engine/src/runner/runner-daemon.js:222-230` · `packages/engine/src/runner/cloud-client.js:211-221`
- **Evidence:** both the transition validation (line 268) and the compare-and-swap filter (line 322) are conditioned on `status !== currentRun.status`. Runner A claims run R (`pending → running`, CAS-protected, correct). Runner B, holding a stale pending list, PATCHes `{run_id: R, status: 'running'}`; the fresh fetch sees `'running'`, so no validation and no CAS → the unconditional update by id+org returns 200 with the run. The daemon treats any returned run as claimed (`runToExecute = claimedRun || candidate`) and executes it concurrently with A.
- **Impact:** two Chrome sessions driving the same portal run — duplicate downloads, duplicate submissions. This is the most consequential correctness defect in the system. Related: the `|| candidate` fallback also executes a run when `claimRun` returns a 2xx without a run payload.
- **Fix direction:** claim with proof — require `expected_status`/a lease token on claim PATCHes, remove the `|| candidate` fallback, and have the server return an explicit "claimed by you" vs "already claimed" distinction.

### C-03 — Portal passwords captured, logged, served, and stored in plaintext ✅
- **Files:** `packages/engine/src/recorder/recorder-injected.js:920-930,769-772` · `apps/desktop/src/main/http-bridge.js:154-169,509-516` · `apps/web/src/components/dashboard/CreatePortalModal.tsx:933-956`
- **Evidence:** the recorder comment says `// Capture the actual typed value (do not redact password)` and emits the raw typed value with `meta.isPassword: true`. Every captured action (including passwords) is also written to the page console via `console.debug/info` (`__WORKFLOW_CAPTURE_ACTION__:<json>`), where it is visible to DevTools, page scripts, and the CDP listener. The bridge then serves recorded actions/recipe unauthenticated (see C-05), and the web app uploads the full recipe (`steps` include the password TYPE actions) into `workflow_definition` in the cloud.
- **Impact:** vendor-portal credentials (a) live in plaintext on disk, (b) are readable by any local process while a recording exists, (c) are stored in the cloud workflow definition, and (d) can be replayed by anyone with access to the record. The `isPassword` flag exists but is never used to redact.
- **Fix direction:** redact at capture time — store a placeholder (`{{secret:portal_password}}`) + field identity, keep the real value in the OS keychain, inject at replay locally; and scrub console logging. This is a design change to the recorder contract, so it needs a plan.

### C-04 — Runner token plaintext in `runner_metadata`, readable/writable by any org member ✅
- **Files:** `apps/web/src/lib/auth/runner-auth.ts:168` · `supabase/schema.sql:86-89` · `apps/web/src/context/DashboardContext.tsx:336-355` · `apps/web/src/app/dashboard/runners/page.tsx:206-230`
- **Evidence:** every heartbeat merges `token: runnerToken` (the raw `rf_live_…` secret) into `wf_organizations.runner_metadata`. The RLS policy is `FOR ALL USING (membership)` — any member can SELECT *and* UPDATE the org row with the anon browser client, and the dashboard reads it directly. A hash column (`runner_token_hash`) already exists and is what auth checks; the plaintext copy defeats it.
- **Impact:** the token authenticates the entire runner API surface (claim runs, read all runs/artifacts, upload, rotate/revoke). Any member session — or any XSS on the dashboard — equals full token holder. Combined with `dashboard/runners` rotate/revoke being token-callable (`runners/route.ts:145-235`), a compromised desktop can lock out all other desktops.
- **Fix direction:** never persist the raw token; store only the hash; return the token exactly once at generation behind an owner/admin check. Split RLS into per-command policies with role checks. Move mutable runner telemetry into a dedicated `wf_runners` table (also fixes M-01 races).

### C-05 — Localhost bridge: no request authentication; CORS is the only control ✅
- **Files:** `apps/desktop/src/main/http-bridge.js:71-100,108-121,126-341`
- **Evidence:** `setCorsHeaders` only *sets response headers* — routes are dispatched purely on path+method, with no Origin/Host/token enforcement (`/record/start|stop`, `/run/stop`, `/discover` all execute regardless). Concrete bypasses: (1) preflight-free POSTs (`text/plain`/form posts, `mode:'no-cors'`) execute server-side even when CORS blocks reading the response — state changes happen; (2) no `Host` validation → DNS rebinding makes cross-site requests same-origin; (3) any `localhost:<port>` origin is trusted with credentials, so any locally served page becomes a privileged caller; (4) requests with no Origin get `Access-Control-Allow-Origin: *`; (5) the deployed dashboard origin is trusted, so any XSS/malicious dep on it controls every visitor's worker.
- **Impact:** any local process or hostile page can start/stop recordings, kill the user's active run, read recipes (including C-03 passwords), and spawn Chrome. Badly behaved time.
- **Fix direction:** per-install bridge secret (provisioned into the dashboard like the runner token) required on every route; server-side Origin *and* Host allowlisting; require `Content-Type: application/json` + a custom header on mutating routes; `Vary: Origin`; rate limits; body caps.

### C-06 — Artifact upload/download pipeline is dishonest (silent loss + fake success + placeholder downloads) ✅
- **Files:** `apps/web/src/app/api/v1/artifacts/upload/route.ts:100-134` · `supabase/schema.sql:58-76` · `packages/engine/src/runner/cloud-client.js:297-328` · `apps/web/src/app/api/v1/artifacts/download/route.ts:44-87`
- **Evidence chain (all four verified):**
  1. The upload route upserts with `onConflict: 'run_id,sha256_hash'`, but no unique constraint/index exists on those columns → PostgREST rejects it and the error is discarded (supabase-js returns `{error}`, the `try/catch` never fires) → the artifact row is never written, yet the route returns **201 + success**, and hardcodes `item_metadata.uploaded_to_cloud: true`.
  2. The engine ignores `uploaded_to_storage` and fabricates a `cloud_storage_path` on 404 **and on `status === 0` (network failure)**, and also when the response omits the field (`cloud-client.js:303,321-324`). The daemon then logs "Uploaded to cloud storage" and records `uploaded_to_cloud: true`.
  3. Fabricated paths use `wf_artifacts/<runId>/<file>` while the real object key is `<orgId>/<runId>/<file>` → downloads of engine-fallback artifacts miss.
  4. When storage lookup fails, the download route returns **HTTP 200 with a synthetic placeholder text file** (`'ReFlow Cloud Artifact Export…'`) named as the requested `.pdf`/`.xlsx`.
- **Impact:** silent data loss that reports success; users downloading "their invoice" receive a metadata stub; operators believe artifacts are backed up to cloud when only local copies exist.
- **Fix direction:** add `UNIQUE (run_id, sha256_hash)` migration; check and surface upsert errors; upsert in `POST /api/v1/artifacts` too; delete the fabrication branches; return 404/502 on missing downloads; have the engine consume the server-returned path only, with retry/backoff.

### C-07 — Run-level execution config is written to the workflow: last dispatch wins; some settings are dropped entirely ✅
- **Files:** `apps/web/src/app/api/v1/runs/route.ts:166-188,208-217` · `supabase/schema.sql:44-55` · `packages/engine/src/runner/runner-daemon.js:296-347` · `apps/web/src/components/dashboard/ExecutionPreflightModal.tsx:758-774`
- **Evidence:** POST `/api/v1/runs` computes `mode/isLoop/loopStepIndex/loopLimit/itemFilter` and persists them into `wf_workflows.workflow_definition`; the response merges them, but `wf_execution_runs` has no such columns, so `GET /api/v1/runs` (the daemon's only acquisition path) never returns them and the daemon silently reads the workflow definition instead. The UI's `item_mode` and `paginate` fields are accepted by the modal, sent to the API, referenced by the engine contract (`runtime-contract.js:143-144`) — and read by nothing in `apps/web`.
- **Impact:** dispatching run B while run A is pending changes A's filter/loop behavior; "new vs all items" and pagination choices are silent no-ops. This is the likely source of "runner executed the wrong items" reports.
- **Fix direction:** add the columns to `wf_execution_runs` in a migration; persist at creation; daemon prefers run-level values (it already tries).

## 3. High findings

### H-01 — Chrome takeover: any process on port 9222 gets adopted or force-killed 🔎
`apps/desktop/src/main/chrome-spawner.js:107-178,195-214` — if any CDP endpoint answers on 9222 it's treated as "ours"; on mode mismatch it runs `netstat | findstr :9222` + `taskkill /F /PID <pid> /T`. A developer's `--remote-debugging-port=9222` session or unrelated app is tree-killed; conversely the worker will drive a browser it didn't spawn and record unrelated tabs. Spawn flags omit `--remote-debugging-address=127.0.0.1` (loopback only by Chrome default). Fix: ownership markers (pid/profile token), kill only owned instances, explicit loopback flag.

### H-02 — Cloud-controlled `target_folder` overrides the local download root ✅
`packages/engine/src/runner/runner-daemon.js:362-381` — `workflowTargetFolder = def.target_folder || workflow?.target_folder` wins over the locally configured directory, and absolute paths are accepted. A cloud workflow (or compromised DB row) can direct artifact writes to arbitrary user-writable paths (e.g. Startup folder). Also three competing defaults exist: desktop/engine `~/Downloads/ReFlow` vs web recorder `~/Documents/ReFlow/Invoices`. Fix: treat target_folder as a subpath hint under the local root; surface the effective path in the UI.

### H-03 — `webhooks/test`: dev-mode auth bypass + incomplete SSRF filter ✅ (bypass) / 🔎 (filter gaps)
`apps/web/src/app/api/v1/webhooks/test/route.ts:18-22,111-135` — auth is skipped whenever `NODE_ENV !== 'production'`, and the private-IP block is also production-gated. The filter compares hostname strings only (no `172.16/12`, `0.0.0.0`, other `127.x`, IPv6/mapped, DNS resolution, trailing dots) and uses default `redirect: 'follow'`. Any dev/staging instance exposed beyond localhost is an open webhook/SSRF proxy with an attacker-controlled payload. Fix: explicit env flag for bypass; enforce filtering in all environments; resolve+pin DNS; `redirect: 'manual'`.

### H-04 — Privilege model: any member (or runner token) can rotate/revoke; roles are never enforced 🔎
`apps/web/src/app/api/v1/runners/route.ts:145-235` + `supabase/schema.sql:86-89` — rotate/revoke accept runner-token auth and replace `runner_token_hash`, marking all workers revoked. Combined with RLS `FOR ALL` on the org row, any member can also rewrite `runner_token_hash`/`plan_tier` from the browser. No route anywhere checks `role`. Fix: owner/admin-only for token ops; token-authenticated callers limited to heartbeat; per-command RLS.

### H-05 — Vault credentials: key derived from orgId (non-secret) + base64 fallback 🔎
`apps/web/src/app/dashboard/settings/page.tsx:497-518,1063-1104` — AES-GCM key = SHA-256(`orgId || 'reflow_default_vault_seed'`); when WebCrypto is unavailable it falls back to `btoa(plaintext)`; ciphertext persists in `localStorage`. The seed is known to anyone with the same origin (and org IDs leak). Fix: server-side encryption with a managed key, or user-supplied passphrase; delete the base64 fallback.

### H-06 — Runner token plaintext at rest in `~/.reflow/config.json`; full token handed to renderer 🔎
`apps/desktop/src/main/config-manager.js:11-12,62-79` (default file perms, no `safeStorage`) + `main.js:298` (`get-config` IPC returns the whole config). On POSIX the file is typically `0644`. Fix: `safeStorage.encryptString` or `0600`+`0700`; return only a masked token to the renderer.

### H-07 — Daemon lifecycle: `stop()` deadlocks a pending sleep; CLI `run` always reports failure ✅
`packages/engine/src/runner/runner-daemon.js:178-181,885-889` — `stop()` clears `_pollTimer`, but that timer is the pending `_sleep()` resolver → the sleep promise never settles and `start()` never returns when stopped while sleeping (masked only by `process.exit` in the CLI). Separately, `executeWorkflow()` invents `run_local_<ts>` ids that every cloud PATCH/register rejects with 404 → `cli run` exits 1 even when the workflow executed fine (`runner-daemon.js:875-882`, `cli.js:406-412`). Fix: resolve pending sleeps on stop; skip cloud telemetry for synthetic ids (or create a real local run mode).

### H-08 — HITL reliability: false positives + watchdog flaws 🔎
`packages/engine/src/runner/hitl-detector.js:78-79,102-112` (URL substrings like `/otp`, any 6–8 char field), `runner-daemon.js:446-476` (unawaited async interval, private `_request`, unfiltered/unbounded run list, swallowed errors), `:457-459` (empty catch hides the deliberate timeout). False positives pause then **fail** valid production runs after 90 s. Fix: require explicit/high-confidence challenge signals or a cloud-declared step; add cooldowns; typed client + status filter; surface timeout error.

### H-09 — Upload envelope: whole-file sync read + base64 (+33 %), fixed 15 s timeout, no retries 🔎
`packages/engine/src/runner/cloud-client.js:283-300,47` — a 200 MB artifact becomes ~270 MB of string in memory; multipart is supported by the cloud route but unused; no retry/backoff on 5xx/408/network anywhere. Fix: stream/multipart upload, per-upload timeout, exponential backoff with jitter, hash while streaming.

### H-10 — Bridge resilience: one port conflict permanently disables the bridge 🔎
`apps/desktop/src/main/http-bridge.js:123-125,343-353` — on `EADDRINUSE` the non-listening server object stays assigned, so every later `start()` returns early forever; `main.js:277-287` only console-errors. The UI shows normal status while "Record Workflow" fails from the web console. Related: `startRecording()` sets `isRecording=true` before the risky `recorder.start()`, leaving phantom "recording" state on failure, and infra failures are mapped to 400. Fix: reset server on error + retry/backoff; expose bridge status to the renderer/tray; set flags only on success with rollback; 5xx for infra errors.

### H-11 — CI/test hygiene: main is red; tests are not wired anywhere 🧪
- `apps/web` — 96/97: `security-tenant-auth.challenge.mjs:211-224` (`F-04.3`) still asserts `dashboard/runners/page.tsx` contains the literal `rf_live_`; the page now receives server-minted tokens (`runners/page.tsx:161,181,224`) and no longer contains it → **stale assertion, red main**.
- Root `npm test` runs only engine tests; `.github/workflows/build-desktop.yml` only builds; no CI runs web tests, web build/lint, desktop tests, or the engine adversarial suite. Failures ship silently (this one did).

### H-12 — Open redirect after login 🔎
`apps/web/src/components/auth/AuthCard.tsx:140` — `window.location.href = redirectedFrom` taken verbatim from `?redirectedFrom=` (`login/page.tsx:11`, `signup/page.tsx:11`); no same-origin validation. Fix: allow only `/`-relative, non-`//` paths.

### H-13 — Middleware burdens every API poll and fails open 🧪+🔎
`apps/web/src/middleware.ts:13-23`, `lib/supabase/middleware.ts:38-41` — matcher includes all `/api/v1/*`; every request (including 3–5 s runner polling and heartbeats) pays a remote `auth.getUser()` round-trip for cookies runners never use; errors fail-open (`NextResponse.next()`). Also the build reports Next 16 deprecation: `middleware` → `proxy`. Fix: skip API paths; use local JWT/claims verification; migrate file convention.

### H-14 — Unbounded disk growth; multiply-copied artifacts; O(n²) checkpoints 🔎
`packages/engine/src/replay/download-manager.js:83` (run folders use second resolution — two same-second runs share a directory), copies at 4 stages (`artifact-download-manager.js:461,143`, `download-manager.js:392`, `runner-daemon.js:732`), no retention/cleanup anywhere for `Run/`, `downloads/`, `recordings/`; `loop-state-coordinator.js:195-205` rewrites the full manifest per item (O(n²) bytes + event-loop blocking).

### H-15 — Dashboard runner flow is a 401 dance that masks server errors 🔎
`apps/web/src/context/DashboardContext.tsx:269-281,319-330` constructs a malformed `rf_live_<org16>` (no secret) as a token header; `runner-auth.ts:58` sees any token and returns 401 before the session-cookie fallback → the API path is dead until a server token exists, and the UI silently falls back to reading the org row directly (which is how C-04's plaintext token reaches every browser). Fix: omit the header when no real token exists; let malformed tokens fall through to session auth.

## 4. Medium findings

### Web API & data layer
- **M-01 runner_metadata concurrency.** Three read-modify-write writers on one JSONB blob (heartbeat `runners/route.ts:160-280`, auth heartbeat `runner-auth.ts:162-177`, theme save `DashboardContext.tsx:451-478`) race: worker entries can vanish; a theme save can resurrect a rotated token. Token generation (`runners/route.ts:70-91`) has a read-then-write race: two GETs both mint, the first caller's token is instantly invalid. Fix: dedicated `wf_runners` table + atomic SQL/RPC; move theme settings out.
- **M-02 No request validation.** No route validates bodies (zod absent): `items_processed = Number(...)` accepts `NaN`(→null)/negatives; `completed_at` accepts any string; `portal_url` stored unvalidated and later navigated to by the desktop; unbounded JSONB. (`runs/route.ts:79-100,239-242`; `workflows/route.ts:58-73`)
- **M-03 No pagination/limits.** `runs`/`workflows`/`artifacts` list queries have no `.limit()`; artifacts builds `.in(run_id, allRunIds)` from all history; PostgREST max-rows truncates silently. (`runs/route.ts:38-52`, `artifacts/route.ts:46-64`, UI `artifacts/page.tsx:515-569`).
- **M-04 Upload limits & filename safety.** Base64/`formData` bodies unbounded; client-supplied `file_size_bytes` trusted; `file_name` interpolated into the storage key without separator/`..` validation. (`artifacts/upload/route.ts:21-77`).
- **M-05 403/404 oracle inconsistency.** Workflows return 403 "belongs to another org" (existence oracle) while runs return deliberately non-disclosing 404. (`workflows/route.ts:144-159` vs `runs/route.ts:103-115`).
- **M-06 Duplicate artifact rows.** Plain insert + per-process daemon dedupe → restart/re-run inserts duplicates; vault UI doesn't dedupe. (`artifacts/route.ts:139-158`, `artifacts/page.tsx`).
- **M-07 No rate limiting anywhere**, and every token attempt costs a DB round-trip; failed attempts unlogged. (`runner-auth.ts`).
- **M-08 Diagnostics endpoint is dead & misleading; docs claim the wrong port.** `runners/diagnostics/route.ts:131-161` reports `token.valid: true` without verifying anything, takes tokens from query strings, and probes CDP 9222 on the *server's* localhost (always fails on Vercel); docs claim it probes bridge port 49152. No consumer in repo.
- **M-09 Inconsistent error codes.** JSON-parse/unexpected → 400 in `runs`/`workflows` POST/PATCH but 500 in DELETEs; DB failure inside `runs` POST becomes 400; PATCH with no updatable fields yields 500. (`runs/route.ts:218-221,290-331`).
- **M-10 Org auto-create race + nondeterministic org.** Concurrent inserts → one 403s; `members[0]` chosen without ordering. (`runner-auth.ts:214-254`).
- **M-11 `GET /auth/signout` is state-changing** (logout CSRF via sameSite=lax top-level navigation). (`auth/signout/route.ts:13-20`).
- **M-12 `itemCount` means two different things** (cloud fallback: step count; desktop bridge: page items) and the UI prints it as items-on-page. (`discover/route.ts:153-159` vs `http-bridge.js:311-319`).
- **M-13 Missing HTTP hardening.** No CSP/HSTS/X-Frame-Options (`next.config.ts` empty; `poweredByHeader` default); Supabase SSR session cookie is `httpOnly:false` (library default) — any XSS reads it.
- **M-14 `artifacts/download` tenant check can skip** when the embedded run is null → authorization not applied (today masked only by FK invariants). Make it fail closed. (`download/route.ts:18-34`).
- **M-15 `runner_token_hash` has no index/unique** though it's the auth lookup key (`schema.sql:14,71-76`).
- **M-16 Storage bucket `wf_artifacts` and its policies are not in the repo** (out-of-band dashboard setup); `upsert: true` on deterministic keys silently overwrites same-name artifacts.

### Engine
- **M-27 Artifact path handling.** `destName` not `path.basename()`-guarded before `path.join` (defense-in-depth; Chrome strips slashes today), and `startsWith(targetDir)` is a string-prefix test (wrong on Windows sibling prefixes). (`runner-daemon.js:724-732`).

## 9. Improvement opportunities ("better ways")

**Architecture & security pattern (highest leverage):**
1. **Bridge auth + contract module.** Per-install bridge secret, server-side Origin/Host enforcement, plus one shared bridge contract module (routes + response schemas) consumed by desktop and web — makes `/record/reset`-style drift impossible.
2. **Server-owned secrets.** Runner token: hash-only storage, one-time reveal, owner/admin role checks, dedicated `wf_runners` table for telemetry (kills C-04, M-01, H-15 at once). Portal credentials: capture placeholders + keychain + replay-time injection (C-03).
3. **One shared auth/route wrapper** (`withAuth(handler, {scope:'org', roles})`) centralizing 401/403 semantics, JSON error shape, no-store, logging; zod per-route schemas. Fixes M-02/M-05/M-09 class issues.
4. **Claim-with-proof protocol** (lease/expected_status) + remove `|| candidate`; persist run config on the run (C-02, C-07).
5. **Honest artifact pipeline**: unique index + surfaced errors + multipart streaming + retry/backoff + 404 on missing downloads (C-06, H-09).
6. **Shared Chrome launcher in the engine** (single profile, explicit loopback debugging address, ownership markers, tree-kill teardown) used by CLI + desktop — removes duplicated spawn logic and H-01.
7. **Centralize bridge endpoint/constants** in web (env or shared constant) — deletes 13 literals; same for token regex/cloud URL defaults.
8. **CI that actually gates**: run all three suites + web build + lint on every PR; fix the stale assertion; add a supabase-local integration test for RLS/schema; add route-handler tests with a mock HTTP server for engine contracts.
9. **Schema migrations backlog**: `UNIQUE (run_id, sha256_hash)`; run-config columns; index on `runner_token_hash`; `supabase_realtime` publication; storage bucket + policies as SQL; RLS bootstrap policies.
10. **UI consolidation**: shared realtime/telemetry hooks with org-scoped topics; server components for first paint; pagination everywhere; fix spinner/countdown/drawer bugs; delete the 12 orphan components (done 2026-10-22).
11. **Desktop hardening & ops**: CSP + explicit sandbox + navigation guards; IPC validation; code signing/notarization; electron-updater with signature verification; bridge status surfaced in UI/tray.
12. **Disk & retention policy**: single canonical artifact directory, retention by age/count, millisecond run folder stamps, non-blocking checkpoint writes.
13. **Observability**: per-day failure counters, surface last poll/heartbeat errors in UI and `doctor`, exit codes, audit log for token/rotate/webhook actions.
14. **Docs truth pass**: reconcile ARCHITECTURE.md claims, dead-code counts, env var matrix; decide schema.sql vs migrations as source of truth.

## 10. What is correct (worth keeping)

- **Runner token crypto** (server): format validation, SHA-256 + `timingSafeEqual`, direct hash lookup (no table scans), revoked → 403.
- **Run status CAS for genuine transitions** + `ALLOWED_TRANSITIONS` state machine + STOPPED aliasing; 409 on real claim conflicts.
- **Tenant scoping discipline** in routes: no route trusts client-supplied `org_id`; cross-org workflow ops rejected; artifacts verify run ownership.
- **Bridge basics**: anchored origin regex + exact configured-origin match (classic `startsWith` bypasses absent); `Origin: null` untrusted; binds `127.0.0.1`; PNA headers; untrusted origins not reflected.
- **Electron fundamentals**: `contextIsolation:true`, `nodeIntegration:false`, genuinely minimal preload (no raw ipcRenderer).
- **Engine env standardization** on `REFLOW_*` with clean precedence (CLI > env > default); no legacy names.
- **Recorder transport design** (marker-based console + direct + parent routing) is robust across iframes/execution contexts, with tests.
- **Checkbox idempotency, date handling, interruption/tab management, selector self-healing** — unusually well tested (65 engine tests, all green).
- **Engine dedupe design** (SHA-256 + tracker + collision suffixes + malicious-portal-name sanitization with tests); cooperative cancellation checked at boundaries.
- **Repo hygiene**: no committed secrets; `.env*`, `data/`, `Run/`, `recordings/`, graphify output ignored; migration idempotent; clean `git status`.
- **Not verified as broken**: single-connect replay path; deps install clean; web build green.
